SPRINT 4 — Longitudinal Intelligence + Contextual Trend Engine (NO visual redesign)

OBJECTIVE:
Meridian must stop interpreting biomarkers as isolated snapshots and begin understanding direction, progression, and historical context.

This sprint introduces the first version of longitudinal intelligence:
- trend awareness
- delta calculations
- improving vs worsening trajectories
- contextual clinical framing
- calmer emotional UX for monitored/improving conditions

IMPORTANT:
- ZERO redesign
- NO typography/color/layout changes
- NO folder restructuring
- KEEP existing architecture
- ONLY add contextual intelligence and rendering logic

==================================================
T001 — Historical Delta Engine
==================================================

Create longitudinal comparison helpers.

NEW FILE:
lib/trend-engine.ts

Add:

- getPreviousBiomarkerValue(slug, currentDate, biomarkers)
- calculateDelta(currentValue, previousValue)
- calculatePercentChange(currentValue, previousValue)
- getTrendDirection()
  returns:
  - improving
  - worsening
  - stable
  - insufficient_data

Rules:

- Ignore same-day duplicates
- Ignore null values

- Use collection_date ordering only

T002 — Clinical Context Layer
==================================================

Add contextual interpretation logic.

NEW helper:
getClinicalContextualState()

Purpose:
Differentiate:
- isolated abnormal
vs
- improving monitored abnormality

Example:
AST:
97 → 64
still abnormal
BUT improving

Should return:
{
  current_state: "high",
  trend: "improving",
  delta: -33,
  contextual_severity: "improving_abnormal"
}

DO NOT downgrade dangerous true criticals.

Hard rule:
trend can soften tone,
but NEVER suppress genuine safety alerts.

context-aware language.

BAD:

Add:

- trend-aware framing

- imply diagnosis
- suppress follow-up recommendations
