# MERIDIAN — URGENT BUG: Onboarding Redirect Loop After Signup

Problem:
After creating a new account, clicking Profile causes an infinite onboarding redirect loop.

Recent changes added smart onboarding guards to:
- MeridianApp.tsx
- dashboard/page.tsx
- profile/page.tsx
- labs/upload/page.tsx
- labs/history/page.tsx

Likely issue:
The protected page guards and onboarding page guards are conflicting.

Investigate the full redirect chain before editing:
- MeridianApp.tsx
- middleware.ts
- onboarding/welcome/page.tsx
- onboarding/identity/page.tsx
- onboarding/profile/page.tsx
- onboarding/goals/page.tsx
- onboarding/connect/page.tsx
- dashboard/page.tsx
- profile/page.tsx
- labs/upload/page.tsx
- labs/history/page.tsx

Goal:
A new authenticated user should move through onboarding exactly once, without loops.

Required behavior:

1. Unauthenticated user:
- / should show welcome/signup
- protected pages should redirect to /onboarding/welcome

2. Authenticated user with incomplete onboarding:
- / should redirect to the first incomplete onboarding step
- dashboard/profile/labs/history should redirect to the first incomplete onboarding step
- onboarding pages should allow the user to stay if that step is needed
- onboarding pages should NOT immediately redirect away unless the required earlier steps are complete

3. Authenticated user with complete onboarding:
- / should redirect to /dashboard
- onboarding pages should redirect to /dashboard
- protected pages should load normally

Define ONE shared helper if useful:
getNextOnboardingStep(profile)

Priority order:
- if no full_name or no birth_date → /onboarding/identity
- else if no biological_profile → /onboarding/profile
- else if no user_profile → /onboarding/goals
- else if onboarding_completed !== true → /onboarding/connect
- else → null

Important:
- Do NOT send incomplete users always to /onboarding/identity if they already completed identity.
- Do NOT allow onboarding pages to fight the protected page redirect.
- Do NOT use email prefix as display name fallback.
- Do NOT modify DB schema.
- Do NOT redesign UI.
- Do NOT touch files outside `.migration-backup/`.

Acceptance criteria:
1. New signup goes to /onboarding/identity.
2. After identity, goes to biological profile step.
3. After biological profile, goes to goals step.
4. After goals, goes to connect step.
5. After connect, goes to dashboard.
6. Clicking Profile mid-onboarding redirects to the correct next incomplete step, not an infinite loop.
7. Completed users can access Profile/Labs/History normally.
8. Build passes.
9. No files outside `.migration-backup/` modified.

Return:
- root cause
- redirect chain fixed
- files changed
- build result
