TASK 1 — Dashboard Safety Alert Precedence
────────────────────

Problem:
Dashboard currently runs a local Safety Engine check for critical biomarkers and sets:

`hasCriticalMarker = true`
`safetyAlert = true`

But a later successful insight API response may call:

`setSafetyAlert(data.safety_alert)`

If `data.safety_alert` is false, it can overwrite the local critical marker safety state.

This creates an inconsistency:
- LabsSavedBlock still shows safety-first copy because it uses `hasCriticalMarker`
- but SolvedBlock safety badge may disappear because `safetyAlert` was overwritten

Required fix:
Safety Engine local critical detection must always take precedence.

If local Safety Engine finds any critical marker:
- `safetyAlert` must remain true
- later insight API response must NOT lower it to false

Acceptable logic:
- `setSafetyAlert(hasCriticalMarker || Boolean(data.safety_alert))`
or equivalent safe precedence.

Do NOT change:
- Safety Engine thresholds
- dashboard design
- dashboard layout
- insight API logic
- lab queries unless needed for this bug
