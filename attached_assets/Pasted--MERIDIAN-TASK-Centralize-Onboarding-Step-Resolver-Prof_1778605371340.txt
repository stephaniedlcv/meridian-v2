You are working on Meridian — a premium Health Intelligence System.

- Vercel

GOAL:
Eliminate onboarding redirect drift, loops, bypasses, and profile save inconsistencies by centralizing onboarding step logic and making Profile updates resilient.

────────────────────
PROBLEM
────────────────────

Onboarding step detection is currently duplicated across multiple files.

This creates risk of:
- redirect loops
- users bypassing onboarding
- users being sent to the wrong step
- completed users seeing onboarding again
- incomplete users accessing Dashboard/Profile/Labs
- different pages interpreting onboarding state differently

Also:
Profile editing still uses `.update()` in some places, which can silently fail if the profile row does not exist.

────────────────────
TASK 1 — CREATE CENTRAL ONBOARDING RESOLVER
────────────────────

Create a shared utility, for example:

`/src/lib/onboarding.ts`

Implement a function:

`getNextOnboardingStep(profile)`

It should return:

- `/onboarding/identity`
- `/onboarding/profile`
- `/onboarding/goals`
- `/onboarding/connect`
- `null`

Logic:

1. If no profile exists:
   return `/onboarding/identity`

2. If missing `full_name` OR missing `birth_date`:
   return `/onboarding/identity`

3. Else if missing `biological_profile`:
   return `/onboarding/profile`

4. Else if missing `user_profile`:
   return `/onboarding/goals`

5. Else if `onboarding_completed !== true`:
   return `/onboarding/connect`

6. Else:
   return `null`

Important:
- Do NOT use email prefix as fallback.
- Do NOT use preferred_name.
- Do NOT assume onboarding is complete unless `onboarding_completed === true`.

TASK 2 — REPLACE DUPLICATED REDIRECT LOGIC
────────────────────

Use the centralized resolver anywhere onboarding state is checked.

Inspect and update:

- `MeridianApp.tsx`
- `/dashboard/page.tsx`

Expected behavior:

Unauthenticated user:
- protected pages redirect to `/onboarding/welcome`

Authenticated incomplete user:
- protected pages redirect to the exact next incomplete step
- not always identity

Authenticated complete user:
- `/` redirects to `/dashboard`
- onboarding pages redirect to `/dashboard`
- protected pages load normally

────────────────────
TASK 3 — PREVENT ONBOARDING LOOPS
────────────────────

Make sure onboarding pages do NOT fight each other.

Rules:

- A user on the correct current step may stay there.
- If user tries to access a later step before earlier data exists, redirect to the correct earlier step.
- If user tries to access an already-completed earlier onboarding step, redirect to the current next step.
- If onboarding is complete, any onboarding page should redirect to `/dashboard`.

Example:

Profile exists with:
- full_name ✅
- birth_date ✅
- biological_profile ❌

Then:
- `/onboarding/identity` → `/onboarding/profile`
- `/onboarding/profile` → stay
- `/onboarding/goals` → `/onboarding/profile`
- protected pages → `/onboarding/profile`

────────────────────
TASK 4 — PROFILE UPDATE UPSERT CLEANUP
────────────────────

Inspect `/profile/page.tsx`.

Any user-editable profile save should use:

`.upsert({ id: user.id, ...fields }, { onConflict: 'id' })`

instead of `.update(...).eq('id', user.id)`.

Specifically check:
- display name edits
- biological profile edits
- user_profile / focus mode edits
- medication edits if present

Rules:
- Use `profiles.full_name`
- Use `profiles.biological_profile`
- Use `profiles.user_profile`
- Use `profiles.birth_date`
- Use `profiles.medications`
- Do NOT create preferred_name.
- Do NOT create display_name.
- Do NOT use email prefix as fallback.

────────────────────
