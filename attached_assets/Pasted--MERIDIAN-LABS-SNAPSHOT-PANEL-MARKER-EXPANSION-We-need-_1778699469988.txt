TASK:
Add progressive in-place marker expansion to Labs Snapshot panel cards.

Current issue:
In /labs/upload Snapshot view:
- Needs Attention shows selected Watch / Attention markers.
- Panel cards show summaries only.
- Panel cards currently rely on “History →” for deeper viewing.

This makes Optimal / normal current markers feel hidden or archived, even though they are part of the current biological state.

Goal:
Labs Snapshot should remain clean by default, but each panel card should allow the user to view current markers for that panel in-place.

Conceptual rule:
Snapshot = current state.
History = how the user got here over time.

Do NOT send users to History just to inspect current markers.

REQUIREMENTS:

1. Keep Needs Attention section

Do not remove or redesign Needs Attention.

It should continue surfacing the most important current markers.

2. Add in-place expansion to each Snapshot panel card

Each panel card should have a current-state CTA:

View markers

When expanded, the CTA should change to:

Hide markers

Use an inline chevron or arrow if it matches existing style.

Do not use a modal.
Do not use a pop-up.
Do not use a bottom sheet for the full panel list.

3. Preserve History, but make it secondary

The current “History →” button should no longer be the primary way to inspect current markers.

Preferred structure:
- Primary CTA: View markers
- Secondary CTA/link: History →

History should mean:
view trend / archive / past results

Snapshot marker expansion should mean:
view current markers in this panel

If space is tight on mobile:
- View markers should be visually primary.
- History can be smaller/secondary/ghost.

4. Default panel state

All panel cards should be collapsed by default.

Collapsed card should show:
- panel name
- marker count
- educational line
- state counts using colored dots
- latest date
- View markers CTA
- secondary History link if retained

Do not display all panel markers by default.

5. Expanded panel content

When a panel expands, show current markers from that panel.

The list must include all states:
- Critical
- Attention
- Watch
- Optimal

Do not only show abnormal markers.

6. Sort expanded markers by state priority

Inside expanded panel, sort markers in this order:

Critical
Attention
Watch
Optimal

Within the same state, keep a stable order if possible.

7. Use density management

Do not make every marker a large range-card by default.

Marker display rules:

A. Critical / Attention / Watch markers:
Use a stronger compact card treatment.
Show:
- marker name
- value
- unit
- state badge
- range bar if valid reference range exists
- ref range label if available

B. Optimal markers:
Use a lighter compact row/card.
Show:
- marker name
- value
- unit
- state indicator/badge
- range summary if available

Do not flood the UI with bright green.
Keep Optimal visually calm.

8. Progressive disclosure within expanded panel

To avoid very long panels, use a collapsed internal limit.

Recommended behavior:
- When a panel is expanded, show:
  - all Critical / Attention / Watch markers
  - plus first 3 Optimal markers
- If more Optimal markers exist, show a small CTA:
  View X more optimal markers
- When tapped, reveal the remaining Optimal markers for that panel.
- CTA changes to:
  Hide extra optimal markers

If simpler implementation is safer:
- Show all markers once panel is expanded, but keep Optimal rows compact.
- Prefer the first approach if feasible without excessive complexity.

9. Individual marker interaction

If individual marker cards already open an existing biomarker detail sheet, preserve that behavior.

In expanded panel:
- tapping any marker should open the existing marker detail sheet when available.
- Do not break the detail sheet.

10. Range bars

Only show range bars when:
- reference_range_min is a finite number
- reference_range_max is a finite number
- reference_range_min < reference_range_max
- value is finite
- marker is numeric
- marker is not flagged/error

Do not invent ranges.

If no valid range exists, show subtle text:
Range data not available.

Do not show blank/ghost range bars with no useful data.

11. Current marker logic

Use the current latest/recent biomarker data already fetched for Labs Snapshot.

Do not change upload/save/OCR logic.

Snapshot should show current markers.
History should remain the full chronological archive.

Do not mix dates confusingly.

If a marker is not from the latest collection date but is being included from the 12-month current snapshot, show subtle metadata:
Last measured: [date]

Only add this if the existing data model makes it easy and safe.
Do not overcomplicate if not already available.

Hide markers
