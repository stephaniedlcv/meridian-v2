MERIDIAN — PANEL ARCHITECTURE + VIEW CONSISTENCY SPRINT

Meridian Labs has now completed:
- ingestion hardening
- renderer refinement
- interpretation coherence
- emotional UX refinement
- explanation coverage expansion
- snapshot/history intelligence parity
- canonical explanation unification
- safety-language calibration

The next major coherence issue identified in audit is:
PANEL ARCHITECTURE FRAGMENTATION.

Currently, the same biomarker can appear under:
- different panel names
- different system groupings
- different educational framing

depending on:
- Snapshot
- Timeline
- Clinical Panels
- Signal Map

This breaks the perception of:
“one coherent intelligence system.”

==================================================
GOAL
==================================================

Create ONE unified biological systems architecture across Labs.

Users should never feel:
- the same biomarker moved categories
- panel names changed arbitrarily
- Snapshot and Timeline organize biology differently
- educational framing changes between views

The system should feel:
- intentional
- clinically coherent
- emotionally stable
- architecturally mature
- biologically logical

==================================================

==================================================

Do NOT:
- redesign layouts
- rewrite renderer math
- modify ingestion
- change biomarker states
- modify DB schema
- alter explanation tone
- add new features
- add wearable systems
- change visual identity

This sprint is:
PANEL COHERENCE + SYSTEM ARCHITECTURE ONLY.

==================================================
SPRINT TASKS
==================================================

━━━━━━━━━━━━━━━━━━━━━━━
1. UNIFY PANEL TAXONOMY
━━━━━━━━━━━━━━━━━━━━━━━

Current issue:
The same biomarkers appear under different panel systems depending on view.

Examples:
- creatinine:
  - Kidney / Renal
  - CMP
  - Comprehensive Metabolic Panel

- ferritin:
  - Vitamins & Nutrients
  - Iron Panel
  - Vitamin & Nutrient Panel

- CRP:
  - Inflammation Markers
  - Inflammation / Cardiac Risk

Required:
Define ONE canonical biological panel taxonomy.

The same biomarker should:
- belong to the same biological home
- use the same panel naming
- preserve the same educational framing
across:
- Snapshot
- Timeline
- Clinical Panels
- Signal Map

━━━━━━━━━━━━━━━━━━━━━━━
2. ESTABLISH PANEL HIERARCHY LOGIC
━━━━━━━━━━━━━━━━━━━━━━━

Current issue:
Some markers belong to broad lab panels (CMP)
while Meridian simultaneously interprets them as biological systems (Kidney, Liver, Electrolytes).

Required:
Define a coherent hierarchy.

Recommended direction:
- top-level biological systems
- optional source-panel attribution underneath

Example:
Primary panel:
Kidney / Renal

Optional metadata:
“Originally measured within Comprehensive Metabolic Panel (CMP)”

NOT the reverse.

Meridian should prioritize:
BIOLOGICAL MEANING
over
lab-order bureaucracy.

━━━━━━━━━━━━━━━━━━━━━━━
3. PANEL EDUCATION UNIFICATION
━━━━━━━━━━━━━━━━━━━━━━━

Current issue:
Three overlapping education systems exist:
- PANEL_EDUCATION
- CLINICAL_PANEL_EDUCATION
- SIGNAL_LAYER_EDUCATION

The same panel receives:
slightly different explanations in different views.

Required:
- consolidate educational architecture
- eliminate redundant parallel systems where possible
- preserve view-specific nuance ONLY when truly necessary

Goal:
Users should feel:
“The app consistently understands this biological system.”
