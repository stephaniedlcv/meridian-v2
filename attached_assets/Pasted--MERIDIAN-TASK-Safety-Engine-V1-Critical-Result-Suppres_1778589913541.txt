GOAL:
Create Safety Engine V1.

Meridian is now storing and displaying real lab data.

Before adding deeper intelligence, Meridian must know when a result is potentially critical and suppress optimization-style language.

CORE PRINCIPLE:
When a biomarker appears potentially critical, Meridian should NOT show:
- optimization guidance
- performance framing
- wellness coaching
- casual next steps
- overly confident interpretation

Instead, Meridian should show calm safety language:
“This result may require prompt medical review. Meridian will not generate optimization guidance for this marker.”

REQUIRED IMPLEMENTATION:

1. Create a Safety Engine utility

Create or update a utility file such as:
`/src/lib/safety-engine.ts`

Implement a deterministic function such as:
`getSafetyStatusForBiomarker()`

It should accept:
- marker_slug
- value
- unit
- biological_profile when available

It should return:
- normal
- critical
- optional reason/message

2. Add MVP critical thresholds

Use a small curated MVP list only.

Do NOT attempt to cover all biomarkers.

Start with common high-risk markers:

Glucose:
- critically low: <= 55 mg/dL
- critically high: >= 300 mg/dL

Potassium:
- critically low: <= 2.8 mmol/L or mEq/L
- critically high: >= 6.0 mmol/L or mEq/L

Sodium:
- critically low: <= 125 mmol/L or mEq/L
- critically high: >= 160 mmol/L or mEq/L

Hemoglobin:
- critically low:
  - female biology: <= 7.0 g/dL
  - male biology: <= 8.0 g/dL
  - unknown profile: <= 7.0 g/dL

Creatinine:
- critically high: >= 5.0 mg/dL

Platelets:
- critically low: <= 20 x10^3/uL
- support equivalent common unit patterns already used in the app

3. Be conservative with units

Only apply thresholds when units are clearly compatible.

If unit is missing or incompatible:
- do NOT force critical classification
- do NOT invent conversions
- return safe/default state

For Phase 1:
- no complex unit conversion
- no aggressive assumptions
