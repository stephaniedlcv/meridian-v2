PROBLEM:
When a user uploads a second lab PDF from the same lab date, Meridian may show:

“Possible duplicate detected”

Example:
- PDF has 15 markers
- only 1 marker from that date may already exist
- user is uploading a legitimate same-day multi-panel lab file

This feels too alarming and can discourage users from uploading routine labs that are split across multiple PDFs.

GOAL:
Refine duplicate detection messaging so Meridian distinguishes between:
1. true duplicate upload
2. same-day multi-panel upload with small overlap
3. high-overlap upload that likely is a duplicate

- any duplicate detection helper used during lab review/save

Find:
- how duplicate markers are counted

- whether it checks marker name + date only
- whether it checks value/unit/panel/source PDF
- how “Save anyway” works

Do NOT change database save logic unless required for this warning refinement.

────────────────────
TASK 2 — CHANGE WARNING LEVEL BASED ON OVERLAP RATIO
────────────────────

Use overlap ratio:

duplicateCount / totalMarkersInCurrentUpload

Suggested behavior:

A) Low overlap:
- duplicateCount <= 2
OR duplicate ratio < 25%

This should be treated as a soft same-day panel notice, not a duplicate warning.

Copy:
“Same-day lab panel detected”
“Some markers from this date may already exist. Meridian can save this PDF and add the new markers to your Lab Snapshot.”

Buttons:
- Primary action remains normal confirm/save
- Secondary: Cancel if needed
- Do NOT make the user feel blocked

B) Moderate overlap:
- duplicate ratio 25%–70%

Copy:
“Possible overlap detected”
“Some biomarkers from this date may already exist. Review before saving, or save anyway if this is a separate lab panel.”

C) High overlap:
- duplicate ratio > 70%

Copy:
“Possible duplicate upload”
“Most markers in this PDF appear to already exist for this date. Save anyway only if this is a corrected or separate file.”

Keep “Save anyway” for this case.
