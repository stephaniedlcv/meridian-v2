We are moving Meridian Labs into a Clinical Stability Hardening Phase focused on rendering consistency, deterministic behavior, and trust reliability.

IMPORTANT:
This is NOT a redesign sprint.
Do NOT change Meridian’s visual identity, spacing philosophy, typography system, glassmorphism treatment, or premium aesthetic language.

The goal is:
- stabilize Labs rendering
- eliminate inconsistent biomarker behavior
- improve trust
- unify clinical logic
- prevent malformed rendering states

CRITICAL PRODUCT DECISION:
Temporarily remove all optimal-range rendering and optimal-based state logic from the UI layer.

For this phase:
- ALL visual positioning
- ALL biomarker state classification
- ALL scale calculations
- ALL color logic

must use ONLY clinical/reference ranges.

Keep database support for future optimal ranges internally if already implemented, but do NOT render or use them in the Labs UI/state engine during this phase.

-----------------------------------
PRIORITY IMPLEMENTATION TASKS
-----------------------------------

1. UNIFIED CLINICAL STATE ENGINE
Replace all mixed optimal/clinical logic.

States should now be determined strictly from:
- reference_range_min
- reference_range_max

State outputs should become deterministic:
- NORMAL
- LOW
- HIGH
- CRITICAL

No “optimal” calculations for now.

-----------------------------------

2. ALL NUMERIC BIOMARKERS MUST ALWAYS RENDER A BAR
Current issue:
Some markers render bars, some do not, even when valid ranges exist.

New rule:
If biomarker is quantitative/numeric:
→ ALWAYS render a scale bar.

Visual hierarchy:
- NORMAL → compact/subtle bar
- LOW/HIGH/CRITICAL → expanded/emphasized bar

Goal:
Maintain visual continuity while still prioritizing abnormal markers.

-----------------------------------

3. REMOVE “RANGE DATA NOT AVAILABLE” FAILURE STATES
The UI should almost never display:
“Range data not available”

Implement fallback hierarchy:

Tier 1:
Use PDF-extracted clinical range if valid.

Tier 2:
Fallback to canonical clinical dictionary.

Tier 3:
Neutral rendering fallback.

UI rendering must NEVER collapse simply because PDF extraction failed.

-----------------------------------

4. IMPLEMENT RANGE VALIDATION / SANITY CHECKS
We are currently seeing malformed ranges such as:
RBC → 0–20.8

Add physiological sanity validation before rendering.

Examples:
- RBC cannot have 0 minimum
- RBC cannot exceed absurd upper bounds
- low >= high should invalidate range
- urine pH cannot exceed physiological boundaries

Invalid ranges should automatically fallback to canonical clinical ranges.

-----------------------------------

5. CBC PANEL COMPLETENESS AUDIT
Current issue:
CBC panels are rendering incomplete despite PDFs containing more markers.

Audit:
- extraction
- normalization
- deduplication
- grouping
- rendering pipeline

Implement deterministic CBC normalization:
- canonical slugs
- canonical ordering
- duplicate consolidation

Also implement:
partial panel detection.

If major CBC markers are missing:
show subtle “Partial Panel Detected” UI state.

-----------------------------------

6. BIOMARKER TYPE SYSTEM
Implement explicit biomarker typing.

Types:
- quantitative
- categorical

Quantitative:
→ render scale bars

Categorical:
→ render chip/status UI
→ NEVER force linear scale rendering

This is especially important for urinalysis.

-----------------------------------

7. CATEGORICAL INTERPRETATION ENGINE
Urinalysis values like:
- Negative
- Trace
- Few
- Moderate
- Many

should NOT all map generically to HIGH/NORMAL.

Implement contextual interpretation mapping per biomarker.

Example:
urine bacteria:
- negative → NORMAL
- rare → NORMAL
- few → WATCH
- moderate → HIGH
- many → CRITICAL

-----------------------------------

8. SEX-SPECIFIC CLINICAL RANGES
Canonical clinical ranges must support:
- female
- male

Use biological_profile already stored in Meridian.

Do NOT use one universal clinical range for all users.

-----------------------------------

9. UNIT NORMALIZATION LAYER
Before rendering:
normalize equivalent units into canonical units.

Prevent scaling inconsistencies caused by:
- mg/dL vs mmol/L
- K/uL vs x10^3/uL
etc.

-----------------------------------

10. IMPORTANT RENDERING RULES
Do NOT:
- redesign Labs page
- change color palette
- alter typography system
- remove premium glassmorphism language
- introduce Tailwind

Meridian uses INLINE STYLES ONLY.

Maintain current visual identity while stabilizing logic and rendering behavior.
