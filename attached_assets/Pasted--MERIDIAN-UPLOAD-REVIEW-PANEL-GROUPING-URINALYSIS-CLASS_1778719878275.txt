TASK:
Fix the Upload Review experience after OCR extraction.

Current problems observed:
1. Urinalysis results are still being misclassified or flagged incorrectly.
2. Some qualitative urine markers are being treated like numeric biomarkers.
3. The review screen does not clearly show which clinical panel the user is confirming.
4. Results appear as a loose list, which makes it harder to verify if the PDF was parsed correctly.

Examples observed:
- Fasting Glucose shows: “Value null mg/dL is outside physically possible range”
- Hemoglobin A1c shows: “Value null /ul is outside physically possible range”
- Urinalysis markers such as Color, Appearance, Acetone, Specific Gravity, Urobilinogen, Nitrite, Epithelial Cells appear under Pending Classification
- Urine values like Color: Yellow / Appearance: Clear / Nitrite: Negative should not be treated as numeric serum biomarkers

GOALS:
1. Add clinical panel grouping to the Upload Review screen.
2. Show the panel name clearly above each group of extracted markers.
3. Handle Urinalysis qualitative/semi-quantitative markers more safely.
4. Prevent qualitative urine markers from being forced through numeric physical range validation.
5. Keep confirmation review clean, clinical, and easy to audit.

3. Urinalysis classification

Add or improve safe matching for common Urinalysis markers.

Recognize these as Urinalysis markers when extracted:
- Color
- Appearance
- Specific Gravity
- pH
- Glucose, urine / Urine Glucose
- Protein, urine / Urine Protein
- Ketones / Acetone
- Blood
- Nitrite
- Leukocyte Esterase
- Urobilinogen
- Bilirubin, urine
- RBC / Red Blood Cells
- WBC / White Blood Cells
- Epithelial Cells
- Bacteria
- Mucus
- Crystals
- Casts

Important:
Do not confuse serum glucose with urine glucose.
Do not confuse CBC WBC/RBC with urine sediment WBC/RBC.

Use surrounding panel context, units, reference text, and marker name when available.

4. Qualitative markers

Urinalysis qualitative markers should support non-numeric values such as:
- Negative
- Normal
- Clear
- Yellow
- None Seen
- Trace
- Few
- Moderate
- Large

These should not be flagged as numeric physical impossibility errors simply because value is not numeric.

If the database currently only saves numeric biomarkers, then qualitative markers should either:
- remain in Pending Classification with clearer messaging, OR
- be excluded from numeric save flow with a safe “qualitative marker” label

But they should not show scary red errors like:
“Value null mg/dL is outside physically possible range”

5. Numeric validation guardrail

Only run numeric physical range validation when:
- marker is expected to be numeric
- parsed value is a finite number

If marker is qualitative:
- do not run numeric physical range validation
- do not show “Value null...” error

If value is missing for a numeric marker:
- show a neutral extraction issue:
  “Value could not be read.”
not a critical medical-style error.

6. Panel context labels

Each marker card in upload review should show or inherit panel context.

Preferred:
- group header shows the panel
- marker cards inside do not need repeated panel label

But for flagged/error cards, include a small panel label if helpful:
Panel: Urinalysis
Panel: Glycemic Panel
Panel: CBC

7. Pending Classification section

Keep Pending Classification if needed, but improve clarity.

Instead of implying these are failed biomarkers, explain:

“These markers were extracted but could not be confidently matched to Meridian’s biomarker dictionary. They will not affect your lab results, counts, or health signals.”

For urinalysis qualitative markers, if they are not saved yet, label them as:
Qualitative urinalysis marker

This avoids making them look broken.
