-----------------------------------
SPRINT 2 — RANGE RESOLVER + VALIDATION LAYER
-----------------------------------

PRIMARY GOALS:
1. Eliminate fragile dependency on OCR-extracted ranges.
2. Remove nearly all “Range data not available” rendering states.
3. Stabilize rendering through deterministic fallback logic.
4. Prevent malformed/impossible ranges from corrupting the UI.

-----------------------------------
IMPLEMENTATION REQUIREMENTS
-----------------------------------

1. IMPLEMENT A STRICT 3-TIER RANGE RESOLUTION HIERARCHY

Tier 1:
Use PDF/OCR extracted clinical reference ranges IF valid.

Tier 2:
Fallback to Meridian canonical clinical dictionary.

Tier 3:
Neutral fallback state if no valid interval exists.

IMPORTANT:
The UI must NEVER collapse simply because OCR failed to extract a range.

-----------------------------------

2. ADD RANGE VALIDATION / SANITY CHECK ENGINE

Before rendering any quantitative biomarker:
validate the extracted range.

Examples of invalid states:
- low >= high
- impossible physiological boundaries
- malformed parsing like:
  RBC → 0–20.8

Examples:
- RBC minimum cannot be 0
- RBC upper bounds cannot be absurdly high
- urine pH cannot exceed physiological ranges
- hemoglobin cannot exceed impossible thresholds

If a range fails validation:
automatically fallback to canonical clinical ranges.

-----------------------------------

3. CREATE CANONICAL CLINICAL FALLBACK DICTIONARY

Implement a centralized canonical dictionary for:
- CBC
- CMP
- Lipids
- Glycemic
- Thyroid
- Vitamin markers
- basic urinalysis quantitative markers

Use:
- sex-specific ranges where appropriate
- biological_profile already stored in Meridian

DO NOT:
- reintroduce optimal ranges
- add optimization logic

Clinical-only architecture remains active.

-----------------------------------

4. IMPLEMENT UNIT NORMALIZATION LAYER

Normalize equivalent units before rendering/scaling.

Examples:
- mg/dL
- mmol/L
- K/uL
- x10^3/uL

Goal:
prevent scale corruption caused by unit inconsistency.

Do NOT attempt a massive universal conversion engine yet.
Focus only on currently supported Meridian biomarkers.

-----------------------------------

5. REMOVE HARD “RANGE DATA NOT AVAILABLE” FAILURE UI

Replace hard failure rendering with:
- fallback interval rendering
OR
- subtle neutral state

The UI should NEVER feel broken because a range is missing.

If absolutely no interval exists:
show a minimal neutral visual state,
NOT an alarming/error presentation.
