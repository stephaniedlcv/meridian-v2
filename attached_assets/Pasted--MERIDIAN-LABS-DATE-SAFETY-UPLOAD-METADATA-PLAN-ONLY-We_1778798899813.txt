Background from audit:
Labs upload currently works but is only partially reliable.

Current findings:
- Upload flow is single-file oriented.
- File is sent as base64 PDF to /api/ocr.
- /api/ocr sends the entire PDF to Claude as a document block.
- Claude returns { lab_date, biomarkers }.
- User confirms in /api/ocr/confirm.
- Confirm saves rows into biomarkers_static.
- Timeline/history rendering is inside labs/upload/page.tsx.
- Multipage PDF is partially supported / unclear because the whole PDF is passed to Claude, but page handling is not enforced by app code.
- Multiple PDFs are not supported.
- Image/photo upload is not supported.
- Missing dates can fall back to new Date().toISOString(), meaning old labs could accidentally be saved as today.
- There is no upload_session_id.
- There is no source_pdf_name.
- There is no source_pdf_hash.
- There is no source_file_type.
- There is no page_count.
- There is no deleted_at / soft delete.
- There is no strong duplicate detection.
- Same-day panels may coexist but are not explicitly grouped as one collection session.

Goal:
Plan the safest first implementation phase for Labs reliability.

Do NOT implement yet.

We want Phase A/B to improve trust without adding multiple PDFs or photo upload yet.
